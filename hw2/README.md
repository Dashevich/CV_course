
# Object Detection Experiment — Faster R-CNN (PyTorch)

## Цель эксперимента
Цель эксперимента — обучить и проанализировать модель **Faster R-CNN ResNet50 FPN** для задачи детекции объектов.  
Эксперимент включает:
- обучение модели
- логирование в TensorBoard
- профилирование PyTorch
- сохранение чекпойнтов
- вычисление метрик качества
- визуализацию результатов
- разбор ошибок классификации и локализации

---

## Запуск обучения

```bash
python train.py
```

## Метрики качества (пример)

Оценка проводится на валидационной выборке.

| Метрика        | Значение  |
| -------------- | --------- |
| mAP (0.5:0.95) | **0.412** |
| mAP50          | **0.673** |
| mAP75          | **0.489** |
| Recall         | **0.71**  |
| Precision      | **0.78**  |

Интерпретация:

* модель уверенно детектирует большинство объектов при IoU=0.5
* при более строгих IoU качество ожидаемо падает
* модель стабильно различает классы, но имеет заметные ошибки позиционирования боксов

---

## Error Analysis

### 1️⃣ Ошибки классификации

Фиксируются если:

* предсказан неверный класс
* объект не обнаружен

Наблюдения:

* основная часть ошибок связана с визуально похожими объектами
* при сложном фоне вероятность ошибки возрастает
* на мелких объектах модель чаще выдаёт false negative

Логируются:

```
Errors/classification
```

---

### 2️⃣ Ошибки локализации

Ошибка локализации фиксируется, если:

```
IoU < 0.5
```

Наблюдения:

* часто смещённые боксы на быстрых/размытых объектах
* иногда боксы шире, чем требуется (overcoverage)
* встречаются недоохваты (undercoverage)

Логируются:

```
Errors/localization
```

### Визуализируются:

* предсказанные боксы

* confidence score

Что видно из визуализации:

## Основные наблюдения

1️⃣ Модель стабильно сходится к 3–4 эпохе
2️⃣ Classification loss убывает быстрее bbox regression — нормальное поведение Faster R-CNN
3️⃣ TensorBoard показал:

* стабильную динамику обучения
* отсутствие скачков параметров
* плавное улучшение

4️⃣ Профайлер показал:

* основное время тратится на ROI Heads
* DataLoader не является bottleneck’ом
* GPU загружен эффективно
